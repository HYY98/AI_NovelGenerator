# 项目概览

## 1. 项目定位

`NovelGenerator` 是一个以 AI 辅助小说创作为核心的前后端项目：用户创建小说及其世界设定，系统通过可配置的 LLM 工作流生成候选内容，用户审阅后再保存为正式数据。

本项目当前仍处于持续重构阶段。本文档描述代码中已确认的边界，不把技术蓝图或空模块当作已交付功能。

## 2. 核心流程

```text
用户输入创意
  → AI 创建小说工作流
  → 生成结构化候选
  → 用户审阅/修改
  → 保存小说、卷、章节、角色、势力和设定卡
  → 章节上下文生成与定稿
```

AI 生成通常通过 HTTP 接口返回状态或 SSE 流式事件；候选生成会留下 `generation_records`，但不会自动覆盖正式章节或设定卡。

## 3. 主要能力

| 领域 | 当前代码边界 |
| --- | --- |
| 小说管理 | 小说、卷、章节的 CRUD 及章节状态管理 |
| 世界设定 | 角色、势力、角色关系、势力关系、角色-势力绑定、设定卡 |
| AI 创作 | 创意扩写、创意提取、核心种子、小说元数据，以及角色、势力、关系、章节和设定卡生成 |
| 定稿 | 章节关联校验、审校和确认提交，记录已确认的故事事件 |
| 配置 | YAML 运行配置、LLM Provider、工作流步骤和提示词管理 |
| 前端 | Next.js 本地化页面、小说创建、写作和设置页面 |

## 4. 前后端边界

- 后端入口为 `main.py`，使用 FastAPI 提供 HTTP API 和 SSE 流式响应。
- 前端位于 `frontend/`，通过 `frontend/src/lib/api.ts` 调用后端；`frontend/next.config.ts` 默认将 `/api/*` 转发到 `127.0.0.1:8200`。
- MongoDB 是持久化数据库；AI Provider 是外部能力，不应与数据库混为一谈。
- `launcher.py` 是 Windows/桌面环境的启动辅助工具，不是业务 API。

## 5. 明确不应推断的内容

- 未发现已实现的多用户登录、JWT 或细粒度权限体系，不应宣称系统具备完整租户隔离。
- `backend/services/novel/` 中的服务是实际业务代码；技术指引中的“蓝图”“推荐 API”属于设计参考，需以路由和服务实现为准。
- `NovelGenerator` 与其他项目（例如 `Toonflow`）的数据库和服务边界不同，本项目使用 MongoDB；当前源码未确认二者存在直接调用关系。
