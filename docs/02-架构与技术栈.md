# 架构与技术栈

## 1. 技术栈

| 层次 | 技术 |
| --- | --- |
| 后端 | Python、FastAPI、Uvicorn、Pydantic、`python-multipart` |
| 数据库 | MongoDB，驱动为 PyMongo Async |
| AI | OpenAI、Google GenAI、Anthropic SDK，以及项目内 Provider 适配层 |
| 前端 | Next.js 16、React 19、TypeScript、Tailwind CSS 4、HeroUI、`next-intl` |
| 测试工具 | 后端 `pytest`；前端 Vitest。具体测试范围以实际文件为准 |
| 桌面启动 | CustomTkinter 启动器；可通过 Electron 以外的本机启动方式运行前后端 |

来源：[`requirements.txt`](../requirements.txt)、[`frontend/package.json`](../frontend/package.json)。

## 2. 后端分层

```text
main.py
  ├─ backend/api              路由与请求模型
  ├─ backend/services/novel   小说领域业务规则
  ├─ backend/services/llm     生成编排、上下文和 Provider 调用
  ├─ backend/llm              Provider、提示词、生成 Schema
  └─ backend/db                MongoDB 客户端、仓储、索引、事务
```

- `main.py` 在 FastAPI lifespan 中加载提示词、连接 MongoDB、初始化索引，并在关闭时释放连接。
- `backend/api/default_routers` 负责常规 CRUD、配置和上传接口。
- `backend/api/llm_routers` 负责 AI 创建小说、角色、章节和设定卡等接口。
- 仓储层通过 `backend/db/base.py` 提供默认软删除和审计字段处理；领域服务负责跨对象校验。

## 3. 请求与生成链路

普通请求大致经过：

```text
Next.js 页面 → fetch 封装 → /api 路由 → Pydantic 校验
  → 领域服务 → Repository → MongoDB
```

AI 请求通常经过：

```text
LLM 路由 → workflow_service
  → 按工作流步骤解析 Provider/超时
  → LLMService 与对应 SDK
  → Pydantic 结构化结果
  → SSE 状态事件或 JSON 响应
  → 生成记录/用户确认后的正式数据
```

`create_novel_router.py` 中的 `create_novel_by_ai` 工作流包含扩写创意、提取创意、生成核心种子和生成小说元数据等步骤。工作流步骤由配置归一化逻辑限定，不能仅凭旧 YAML 中的自定义步骤断言运行时支持。

## 4. 数据与文件

- MongoDB 连接由 `backend/db/mongo.py` 管理，使用 `AsyncMongoClient`，启动时主动 `ping`。
- 连接串和数据库名可由 `NOVEL_GENERATOR_MONGODB_URL`、`NOVEL_GENERATOR_MONGO_DATABASE_NAME` 覆盖；实际值不应写入文档或日志示例。
- 数据集合与索引由 `backend/db/indexes.py` 初始化。
- 上传文件和封面属于文件系统资源；路由与静态目录的具体权限需结合部署环境检查。
- `backend/llm/schemas` 是生成输入/输出结构，不等于 MongoDB 的完整持久化 Schema。

## 5. 配置与提示词

- 默认配置：`backend/config/config_default.yaml`。
- 运行配置：`backend/config/config.yaml`，通常包含 Provider 地址和密钥，应保持本地私有。
- 配置读写实现：[`backend/config/config.py`](../backend/config/config.py)。
- 提示词选择与检查：`backend/llm/prompts`。
- 工作流可配置默认 Provider、步骤 Provider 和超时时间；程序会规范化 Provider 的 base URL。

## 6. 当前架构边界

- CORS 配置不是鉴权机制；当前 `main.py` 的跨源设置较宽松，公开部署前必须另行设置访问控制。
- 事务支持取决于 MongoDB 部署能力和调用方是否把同一 session 传入所有写操作；降级到顺序写入时不具备跨集合原子性。
- 尚未通过本次文档工作运行验证开发、前端构建、生产启动或外部 Provider 调用。
