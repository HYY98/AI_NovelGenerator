# 数据模型

## 1. 存储概览

项目使用 MongoDB，异步客户端和连接管理位于 [`backend/db/mongo.py`](../backend/db/mongo.py)。默认连接配置为 `mongodb://localhost:27017`，默认数据库名代码回退值为 `novel_generator`；实际运行配置可能由 `backend/config/config.yaml` 或环境变量覆盖。

仓储位于 [`backend/db/repositories`](../backend/db/repositories)。常规读操作默认排除 `is_deleted=true` 的文档。

## 2. 集合与职责

| 集合 | 职责 | 关键标识 |
| --- | --- | --- |
| `novels` | 小说基本信息与统计 | MongoDB `_id` |
| `volumes` | 小说卷、顺序和摘要 | `_id`、`novel_id`、`order_index` |
| `chapters` | 章节正文、状态和上下文快照 | `_id`、`chapter_id`、`novel_id`、`volume_id` |
| `characters` | 角色档案和成长信息 | `_id`、`character_id`、`novel_id` |
| `factions` | 势力档案 | `_id`、`faction_id`、`novel_id` |
| `character_relations` | 角色之间的关系 | `_id`、`relation_id`、角色业务 ID |
| `faction_relations` | 势力之间的关系 | `_id`、`relation_id`、势力业务 ID |
| `character_faction_bindings` | 角色与势力的成员关系 | `_id`、`binding_id`、两端业务 ID |
| `setting_cards` | 地点、物品和规则卡 | `_id`、`card_id`、`type` |
| `generation_records` | AI 生成请求、输入快照和候选结果 | `_id`、`generation_id` |
| `story_events` | 章节中确认或提议的故事事件 | `_id`、`event_id` |
| `id_sequences` | 按小说和实体类型分配业务编号 | `novel_id`、`entity_type` |

## 3. ID 与作用域

- MongoDB `_id` 通常为 `ObjectId`，API 层可能将其序列化为字符串。
- 角色、势力、关系、绑定、设定卡、生成记录和故事事件还使用业务 ID，例如 `char_000001`、`fac_000001`、`gen_000001`。
- 业务 ID 通常在 `novel_id` 作用域内编号，不应默认理解为全库唯一。
- 章节关联校验需同时检查业务 ID 是否属于当前小说、目标对象类型是否正确以及是否处于可见状态。
- 文档中出现 `novel_id`、`volume_id` 等字段，不代表 MongoDB 已声明同名外键或数据库级联。

## 4. 审计与软删除

基础仓储 [`backend/db/base.py`](../backend/db/base.py) 为插入记录设置 `created_at`、`updated_at`、`is_deleted` 和 `deleted_at`；更新会刷新 `updated_at`。查询默认加入 `is_deleted=false`，但管理员或维护代码可显式包含已删除数据。

部分关系和角色数据还保存 `is_active`、`deletion_sources` 等业务状态。软删除后业务 ID 通常仍受唯一索引约束，因此不应复用旧 ID。

## 5. 索引与一致性

索引定义集中在 [`backend/db/indexes.py`](../backend/db/indexes.py)，主要保证小说内的顺序、业务 ID、章节编号、名称规范化和活动关系唯一性。索引是代码声明的初始化目标；是否已经在目标 MongoDB 实例成功建立，需要查看启动日志或数据库本身。

部分索引创建失败会记录告警并继续启动，因此部署检查不能只看进程是否启动。

## 6. 事务与补偿

[`backend/db/transaction.py`](../backend/db/transaction.py) 支持 `disabled`、`auto` 和 `required` 等事务模式。`auto` 在 MongoDB 不支持事务时可降级为顺序写入；这不等于跨集合原子操作。

[`backend/db/created_write_compensation.py`](../backend/db/created_write_compensation.py) 为部分批量创建提供按版本和业务标识匹配的补偿删除。补偿可能部分成功，不能当作通用回滚；ID 序列也可能出现空号。

## 7. 模型来源和漂移

- 持久化事实以仓储实现、索引和实际写入路径为主。
- `backend/llm/schemas` 描述 LLM 结构化输入输出，不代表所有数据库字段。
- `frontend/src/types` 是前端交互类型，也可能滞后于后端。
- `backend/db/repositories/context_memory_repository.py`、`outline_repository.py`、`worldbook_repository.py` 当前为空，不能据文件名认定对应功能已经实现。
- `backend/db/indexes.py`、仓储和类型快照出现差异时，应以当前调用路径和数据库迁移结果复核，不可直接复制旧类型定义。
