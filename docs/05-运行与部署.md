# 运行与部署

## 1. 运行前提

项目包含 Python 后端和 Next.js 前端，另有 Windows 启动器。依赖来源：

- 后端：[`requirements.txt`](../requirements.txt)
- 前端：[`frontend/package.json`](../frontend/package.json)
- 后端入口：[`main.py`](../main.py)
- 启动器：[`launcher.py`](../launcher.py)

本项目当前未提供已确认可复用的 `Dockerfile` 或 Compose 配置。不要把其他项目或测试环境的容器说明直接套用到本项目。

## 2. 默认端口

| 服务 | 默认端口 | 配置来源 |
| --- | ---: | --- |
| FastAPI 后端 | `8200` | `backend/runtime.py` |
| Next.js 前端 | `3300` | `backend/runtime.py` |
| MongoDB | `27017` | MongoDB 默认连接回退值，实际可被配置覆盖 |

> 本机（开发机）实测：MongoDB 为便携版实例，监听 `127.0.0.1:27018`，数据库名 `my_database`，以 `backend/config/config.yaml` 为准，与默认回退值不同。

后端监听地址由 `main.py` 设置为 `127.0.0.1`。前端开发服务器和后端端口必须保持一致；`frontend/next.config.ts` 当前 rewrite 目标明确写为 `http://127.0.0.1:8200`，修改后端端口时需同步检查该文件或使用项目已支持的环境覆盖方式。

## 3. 配置原则

- 默认配置：`backend/config/config_default.yaml`。
- 本地运行配置：`backend/config/config.yaml`，由 `backend/config/config.py` 合并加载；文件通常包含 Provider 密钥，应保持私有。
- MongoDB 进程级覆盖：`NOVEL_GENERATOR_MONGODB_URL`、`NOVEL_GENERATOR_MONGO_DATABASE_NAME`。
- 端口覆盖：`NOVEL_GENERATOR_BACKEND_PORT`、`NOVEL_GENERATOR_FRONTEND_PORT`。
- 调试开关：`NOVEL_GENERATOR_BACKEND_DEBUG=1`，或后端参数 `--debug` / `--no-debug`。
- 前端 API：`NEXT_PUBLIC_API_BASE`；为空时使用相对路径。

安全示例只写占位符：

```text
NOVEL_GENERATOR_MONGODB_URL=mongodb://127.0.0.1:27017
NOVEL_GENERATOR_MONGO_DATABASE_NAME=novel_generator_local
NOVEL_GENERATOR_BACKEND_PORT=8200
NOVEL_GENERATOR_FRONTEND_PORT=3300
```

不要把真实 API Key、密码、云服务地址或生产连接串填入文档、Issue 或日志。

## 4. 本地开发运行

后端依赖安装和启动命令应在项目根目录执行；前端依赖和命令应在 `frontend/` 执行。前端还需要 **Node.js >= 20.9**（Next.js 16 要求；本机实测使用 24.19.0 LTS），未安装 Node.js 时 `npm` 不可用。以下命令已在 2026-09-16 的 Windows 开发机上实测通过：

```powershell
# 项目根目录
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py

# 另开终端，在 frontend 目录
npm install
npm run dev
```

Windows 启动器由 [`start.bat`](../start.bat) 调用 `.venv\Scripts\pythonw.exe launcher.py`。启动器会管理本机前后端端口设置，端口必须不同且处于 `1` 到 `65535` 范围。

## 5. MongoDB 与持久化

后端启动生命周期会依次加载提示词、连接并 `ping` MongoDB、初始化索引；连接失败时应先检查 MongoDB 服务、URI、数据库名和网络权限。数据不保存在项目 Git 文件中，而保存在配置指定的 MongoDB 实例。

建议维护流程：

1. 先确认目标 URI 和数据库名，避免误操作其他环境。
2. 使用 MongoDB 官方工具或平台能力进行备份，并记录备份时间。
3. 在隔离副本验证恢复和索引初始化。
4. 再执行版本升级或数据迁移。

项目支持的事务模式取决于 MongoDB 部署能力；`auto` 可能降级为顺序写入，不应把“服务启动成功”当作事务能力证明。

## 6. 前端与后端联调排障

| 现象 | 优先检查 |
| --- | --- |
| 页面无法打开 | 前端进程、`3300` 端口和 Node 依赖 |
| `/api` 请求失败 | 后端是否监听 `8200`、`frontend/next.config.ts` rewrite、`NEXT_PUBLIC_API_BASE` |
| 启动时数据库错误 | MongoDB 是否可达、URI/数据库名、超时配置 |
| AI 请求失败 | Provider 类型、根地址、模型名、密钥和工作流步骤配置；不要把密钥贴入日志 |
| SSE 中断 | 浏览器网络、反向代理缓冲、后端日志以及请求 ID |
| 端口冲突 | `backend/runtime.py` 和启动器设置是否配置了不同的有效端口 |

## 7. 部署边界

本项目文档目前只确认本机后端、前端和启动器路径。生产部署前必须补充认证、网络隔离、TLS、日志脱敏、备份、监控和最小权限方案；CORS 不能代替这些控制。
