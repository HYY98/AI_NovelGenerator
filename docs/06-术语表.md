# 术语表

| 术语 | 含义 | 易混点 / 关联 |
| --- | --- | --- |
| 小说（Novel） | 一个创作项目的根对象，包含元数据、卷、章节和世界设定 | 见[数据模型](./03-数据模型.md) |
| 小说作用域 | 由 `novel_id` 界定的业务数据范围 | 业务 ID 通常在小说内编号，不代表全库唯一 |
| 卷（Volume） | 小说内的分卷对象，用于组织章节 | `volume_id` 可能是 MongoDB `ObjectId` |
| 章节（Chapter） | 小说正文单元，包含正文、状态、摘要和关联信息 | 有 `draft`、`editing`、`finalized` 等状态 |
| 角色（Character） | 小说中的人物档案 | `character_id` 是业务 ID，`_id` 是 MongoDB 主键 |
| 势力（Faction） | 小说世界中的组织、阵营或群体 | 与角色的隶属关系单独保存在绑定集合 |
| 角色关系 | 两个角色之间的叙事关系 | 不等于角色档案中的静态字段 |
| 势力关系 | 两个势力之间的关系 | 方向和活动状态由关系数据表达 |
| 角色-势力绑定 | 角色加入、隶属或隐藏关联某个势力的记录 | `primary/secondary/covert` 是成员关系类型 |
| 设定卡（Setting Card） | 可复用的世界设定条目 | 当前包括地点、物品、规则三类 |
| 规则卡 | 对世界运行方式或硬规则的结构化设定 | “建议”不等于代码强制校验 |
| 候选（Candidate） | AI 生成、等待用户审阅的结果 | 不应直接当作正式正文或正式卡片 |
| 采纳（Accept） | 用户确认采用候选结果的动作 | 采纳状态会记录在生成记录中 |
| 生成记录（Generation Record） | AI 请求的输入快照、结果、Provider、状态和采纳信息 | 生成不是无状态过程，记录会落库 |
| 故事事件（Story Event） | 章节中提出或确认的角色/剧情变化事件 | 定稿服务记录确认结果，但不自动改写角色档案 |
| 定稿（Finalize） | 章节经过审校并确认提交为稳定版本 | 已定稿重开通常进入 `editing` |
| ObjectId | MongoDB 常用的 `_id` 类型 | 不要与业务 ID 字符串混用 |
| 业务 ID | 面向小说领域的编号，如 `chap_000001` | 通常受 `novel_id` 作用域约束 |
| 软删除 | 使用 `is_deleted` 等字段标记删除而不立即移除 | 默认查询会排除软删除记录 |
| SSE | Server-Sent Events，服务器向客户端持续推送事件 | AI 工作流可用它推送步骤状态 |
| Provider | LLM 服务提供方及其连接配置 | Provider 配置含密钥，必须私有 |
| 工作流（Workflow） | 多个 AI 步骤组成的业务生成流程 | 每步可解析 Provider 和超时 |
| Prompt | 指导模型生成的提示词 | 提示词约束不自动等同于程序校验 |
| 事务降级 | MongoDB 不支持事务时，`auto` 模式改为顺序写入 | 顺序写入不具备跨集合原子性 |
| 补偿写入 | 失败后按创建批次条件尝试删除部分已写数据 | 不是通用回滚，可能部分成功 |
| CORS | 浏览器跨源资源共享策略 | 不是登录、鉴权或公网安全边界 |
| LLM | Large Language Model，大语言模型 | 具体能力取决于 Provider 和模型配置 |
